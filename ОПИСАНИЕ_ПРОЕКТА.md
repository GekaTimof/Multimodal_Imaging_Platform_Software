# Мультимодальная платформа для обработки изображений

## Общее описание проекта

Мультимодальная платформа для обработки изображений представляет собой комплексное программное решение для управления научными приборами через настольное приложение и Raspberry Pi. Платформа предназначена для управления спектрометром, камерой и анализа лунок через интуитивно понятный графический интерфейс с поддержкой нескольких языков.

## Архитектура системы

Система состоит из двух основных компонентов, которые взаимодействуют через API:

### 1. DesktopApp (Настольное приложение)
- **Назначение**: Пользовательский интерфейс и панель управления
- **Место выполнения**: Работает на компьютере пользователя
- **Ответственность**:
  - Графический интерфейс на PyQt5 для управления камерой
  - Отображение видеопотока в реальном времени
  - Интерфейс управления настройками
  - Захват и сохранение изображений
  - API-клиент для связи с Raspberry Pi

### 2. RaspberryPi (Сервер управления оборудованием)
- **Назначение**: Управление оборудованием и обработка данных
- **Место выполнения**: Работает на Raspberry Pi 5
- **Ответственность**:
  - Управление аппаратным обеспечением камеры
  - Управление спектрометром
  - Управление базой данных (единый источник правды)
  - FastAPI сервер для удаленного управления
  - Сервер видеопотока

## Принцип работы

### 1. Запуск системы
1. Запускается сервер на Raspberry Pi с FastAPI
2. Инициализируется база данных DevicesSettings.db
3. Запускаются службы управления оборудованием
4. Запускается настольное приложение на компьютере пользователя

### 2. Взаимодействие компонентов
- DesktopApp выступает как API-клиент
- Raspberry Pi предоставляет RESTful API
- Все операции с настройками проходят через API
- База данных находится исключительно на Raspberry Pi

### 3. Поток данных
1. Пользователь взаимодействует с GUI на DesktopApp
2. DesktopApp отправляет запросы на Raspberry Pi через API
3. Raspberry Pi обрабатывает запросы и управляет оборудованием
4. Данные возвращаются через API и отображаются в GUI
5. Видеопоток передается через MJPEG стриминг

## API интерфейсы

### Базовый URL
```
http://10.43.70.189:8000/api
```

### Основные эндпоинты

#### Настройки камеры
- `GET /api/settings/camera` - Получить текущие настройки камеры (слот 0)
- `GET /api/settings/camera/slot/{slot_id}` - Получить настройки для конкретного слота (0-9)
- `GET /api/settings/camera/slots` - Получить все слоты настроек камеры
- `POST /api/settings/update` - Обновить один параметр
- `POST /api/settings/camera` - Обновить все настройки камеры
- `POST /api/settings/camera/save-slot/{slot_id}` - Сохранить настройки в слот
- `GET /api/settings/camera/validation-rules` - Получить правила валидации параметров

#### Общие настройки
- `GET /api/settings/{table_name}` - Получить настройки из любой таблицы
- `GET /api/health` - Проверка состояния сервера

#### Управление спектрометром
- `GET /api/spectrometer/data` - Получить спектральные данные
- `POST /api/spectrometer/calibrate` - Калибровка спектрометра
- `POST /api/spectrometer/integration-time` - Установить время интеграции

## Технологический стек

### DesktopApp
- **Фреймворк**: PyQt5
- **Архитектура**: MVC паттерн с модульным дизайном
- **Интернационализация**: JSON файлы переводов
- **Конфигурация**: JSON файл настроек
- **Обработка изображений**: OpenCV
- **HTTP клиенты**: requests

### RaspberryPi
- **Веб-фреймворк**: FastAPI
- **Сервер**: Uvicorn
- **База данных**: SQLite
- **Управление оборудованием**: GPIO, USB интерфейсы
- **Обработка данных**: NumPy, SciPy
- **Видеопоток**: MJPEG стриминг

## База данных

### Принцип единой базы данных
- **Только одна база данных**: `/RaspberryPi/DevicesSettings.db`
- **Расположение**: Исключительно на Raspberry Pi
- **Доступ**: Только через эндпоинты FastAPI

### Таблицы базы данных
- `CameraSettings`: Параметры и конфигурации камеры
- `SpectrometerSettings`: Параметры спектрометра
- `PositionerSettings`: Настройки позиционера

## Система безопасности

### Разделение компонентов
- DesktopApp НЕ имеет прямого доступа к базе данных
- RaspberryPi предоставляет полный API для всех операций
- Все параметры и операции валидируются на сервере
- Отсутствие прямого управления оборудованием из DesktopApp

### Защита данных
- Параметры передаются через HTTPS (в производственной среде)
- Валидация всех входных данных
- Обработка ошибок и исключений
- Логирование операций

## Преимущества архитектуры

1. **Четкое разделение**: Настольное приложение и оборудование полностью разделены
2. **Единый источник правды**: Только одна база данных устраняет проблемы синхронизации
3. **Масштабируемость**: Несколько DesktopApp могут подключаться к одному RaspberryPi
4. **Поддерживаемость**: Изменения в оборудовании не влияют на код UI
5. **Тестируемость**: Каждый компонент может тестироваться независимо
6. **Удаленный доступ**: API обеспечивает возможности удаленного управления
